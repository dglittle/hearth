# output cards: one per reply-able item, self-contained, imp/urg rated, linked

**One output card per item of interest.** The operator replies/archives per
card, so each independently reply-able or archivable thing gets its own card:
each new ticket, each approval ask, each FYI. Summary/digest cards are fine
ALONGSIDE the per-item ones (linking them as refs), never as a substitute.
When items share context, repeat the relevant context in each (a line or two
+ links) so every card stands alone. Split answer-cards from
pending-ask-cards so the archivable part doesn't drag the pending part along.
Title = the one-sentence summary.

**Priority (importance/urgency columns, each 1–10):** the board sorts by an
operator-controlled slider. importance = impact on the operator's work/money
(9–10 = urgent tickets/money/approvals blocking income, 5 = useful context,
1–2 = routine FYI); urgency = how soon they must look (9–10 = today/blocking,
5 = this week, 1–2 = whenever). When a new output supersedes an older unread
one, down-rate the old card so it sinks.

**Self-contained replies:** when replying to an operator reply, assume they
have ALREADY archived the card they replied to and every earlier card in
that chain. Each reply must stand alone: restate the needed context in a few
lines, carry forward ALL still-open asks from the chain, and re-link every
relevant artifact. (Card bodies persist in the chain — walk parents — but
what the OPERATOR SEES is only the new card.)

**Links:** every output card includes links to the relevant artifacts
(tickets, threads, PRs, docs). Bare URLs render clickable; the url column
holds the primary ↗ link.
